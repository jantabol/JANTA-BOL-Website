## Implemented REVIEW_ONLY SQL
`JANTA_BOL_PHASE_4_WORKING/db/T079_YOUTUBE_VIDEO_LEDGER_PG17_REVIEW_ONLY.sql` creates a strictly private, RLS-enabled, service_role-only immutable upload-intent journal:
- Unique key `(article_id, article_version, channel_id, media_sha256)`: one job per exact article revision+video+channel. No repeated Google videos.insert create session on identical retries.
- Only `private-editorial/youtube-news/<article-id>/<filename>.mp4` source accepted, Founder approval hash and independent rights proof hash required, 50 MiB max. **NEVER grievance media**.
- Durable states RESERVED → INITIATING → SESSION_OPEN → UPLOADING → RECEIPT_PENDING → PRIVATE_VERIFIED. Any ambiguous request lands in UNKNOWN, from which another init is impossible without separate reconciliation. Exactly one initiation per job (`attempt_count <= 1`).
- Server-only AES-GCM ciphertext + IV columns to hold a future Google resumable session URL; never put a session URL/token into public browser/social rows. Ledger provider video ID is unique.
- Three `public.jb_t079_video_*_internal` functions execute as **SECURITY INVOKER** (no SECURITY DEFINER RLS bypass); `REVOKE EXECUTE FROM PUBLIC`, grant only `service_role`; schema private denied to `anon` and `authenticated`. Operations are DB-atomic and reject invalid transitions, second INITIATING, wrong lease and duplicate idempotency.
- No automatic release after a network error; UNKNOWN remains quarantined even if an old worker dies. Confirmation for PRIVATE_VERIFIED must be independent Google channels.mine + videos.list evidence from a separate reviewed worker, NOT generated by the ledger itself.
